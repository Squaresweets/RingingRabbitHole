This is all of plain bob doubles. You can imagine that to share methods this would be quite a lot of information to share, so lets think of ways to compress it down. We found out in the first episode that the movement of the bells in each lead is the same, so to recreate the whole method we only need the first lead. This grid view is better, but we can do better. The grid view only shows how the bells move in a lead, it does not specify bell numbers. To store this pattern we can split it into all of the changes and encode each of them.
Looking at each change, notice how they are made up of crosses and lines. Each line represents a bell making a place, and if a bell isn't making a place it is swapping positions with another bell. Looking at all possible changes on 5 bells, you can see that this pattern holds, we only have crosses and straight lines. An intuiative way to store a change is thus to store which bells make places. One thing I haven't talked about yet is symmetry. This is a topic I will cover further in a future video, but in short many methods have some form of palindromic symmetry. This means that if we look at a singular lead, ignoring the next lead head, we can read this lead backwards and still get the same lead. This means that we only need to store one half of this lead and then flip it to get the rest. This gives us another trick to compress our notation, we only need to store half of the notation. To expand it to the full notation you just have to take all the notation up to the last change before the comma, flip it, and put it after the comma. You technically have to do this to both sides of the comma, but since there is only one on the right hand side we do nothing. A minor point is that by itself this isn't enough to generate a method, for example this same notation could generate any of these methods, so you also need to store the stage alongside the notation. When using more than 9 bells we start using the alphabet instead of numbers. Eleven and twelve are E and T, and then we start from A excluding any we have already used. We also exclude I so as not to confuse it with 1.

Describing calls is simple with this notation. When a call occurs, it overrides a small amount of place notation at the end of a lead. The amount of notation and the position where these changes occur change from method to method, but most of the time, it is one piece of notation changed at the lead end. For plain bob doubles, a bob changes the “125” change to a “145” change, and a single changes it to a “123” change.

As a side tangent, there are sometimes inconsistencies about leaving some numbers out in the notation. For example, in a minimus method, if we had the notation “1”, there must be some other bell which also makes a place, as there are 3 other bells. Some sources may correct this to 12 and some to 14. For example, the single in stedman doubles has the notation “45”; however, this is short for “ 345” not “145”. Be careful with this, and when in doubt, write the notation out in full to avoid ambiguity.

This is known as place notation and it plays a vital role in how methods are stored and shared. But how does it work?
First, lets examine the first lead of our method. Between each row, certain pairs of bells swap and certain bells stay in the same position. In the first change you can see that the bell in fifths place stays in the same place, while the other bells swap around, thus the place notation for this change would simply be “5”.
